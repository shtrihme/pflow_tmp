# ProductFlow — пустой проект

## Создать проект по этому шаблону

**GitHub UI:** кнопка «Use this template» → «Create a new repository» → выбери **Private**.

**GitHub CLI:**
```bash
gh repo create my-project --template shtrihme/pflow-blank --private --clone
cd my-project
```

**Через агента** (в любом Claude Code-сеансе с доступом к GitHub):
> Создай приватный репозиторий из шаблона shtrihme/pflow-blank с именем my-project и склонируй его.

---

Чистый старт под твою продуктовую модель. Воркспейс преднастроен — можно сразу работать с агентом.

- **MCP-сервер `pflow`** подключён через `.mcp.json` — агент видит инструменты `pflow_*` и работает с моделью напрямую, без чтения файлов вручную.
- **`AGENTS.md`** — инструкция агенту: роль, инструменты, DSL, правила «зелёной» модели.
- **`CLAUDE.md`** — правило «MCP first» и сценарий «помоги начать».
- **`docs/`** — справочники по DSL и возможностям инструмента.

---

## Быстрый старт

Открой агента и напиши:

> Помоги начать новый pflow-проект. Я работаю над `<кратко про продукт>` для `<целевая аудитория>`.

Агент уточнит нишу (1–2 вопроса), проведёт кабинетный ресёрч и через `pflow_scaffold` создаст первые сущности — Сегмент, Работу, Канвас. После каждой правки прогоняет `pflow_validate`.

Альтернативные стартовые промпты:

- «У меня есть стратегия в Notion, преобразуем её в pflow» — агент попросит вставить текст и поведёт по структуре.
- «Покажи как устроена pflow-модель» — агент пройдёт по теории с примерами через `pflow_scaffold` (без записи файлов).

---

## Самостоятельный старт

Открой `AGENTS.md` — там полный список сущностей DSL, канонические сниппеты и точные enum-литералы. Создай в корне файл `units.pflow` с одним Юнитом — и поехали.

---

## VS Code

Если работаешь в VS Code — установи расширение ProductFlow. Оно добавляет дерево аспектов, реестр сущностей, диаграмму связей и inlay-хинты прямо в редакторе. Расширение подхватывает тот же `.mcp.json` — агент и IDE видят одну модель.
