# Работа с pflow через агента

**80%+ изменений модели делает агент** (Claude Code или совместимый MCP-клиент). Руками — мелкие правки, навигация по outline/inlay, визуальный осмотр диаграммы. Это не теоретическая возможность — это рабочий контур, под который инструмент специально спроектирован.

---

## Почему через агента

В классическом workflow с Notion/Confluence агент пишет вслепую: ссылки на несуществующие сущности, опечатки в enum-литералах, расхождения между документами видны только при ревью.

В pflow агент видит **то же, что человек в редакторе**, через MCP-сервер:

| PM в редакторе | Агент через MCP |
|---|---|
| `⚠️ Канвас не покрыт ни одной Услугой` | `pflow_validate` → этот warning в JSON |
| autocomplete после `Тип:` | `pflow_enums` → допустимые значения |
| F12 на Сегменте → файл и строка | `pflow_locate` → `{file, uri, range}` |
| F2 → переименование во всём workspace | `pflow_refs` → все incoming/outgoing |
| Tab → scaffold с tab-stops | `pflow_scaffold` → DSL-заготовка |
| Hover «В этом проекте: 2 Сценария» | `pflow_context --focus name` → markdown среза |

Если агент написал Предложение без привязки к Работе — это сразу в его контексте на следующем `pflow_validate`, и он чинит до того, как отдать вам PR.

## Цикл изменения: попросил → агент → варнинги → уточнил → fix

Один пример «от и до». PM хочет добавить операционную услугу под существующий Канвас «Чистка ковров премиум-сегмента».

### 1. Запрос в чат

> «Добавь Услугу чистка_премиум, реализующую Предложение «профессиональная химчистка». Цена 350₽/м², статус идея.»

### 2. Агент собирает контекст

```
pflow_locate { name: "профессиональная химчистка", type: "Solution" }
→ examples/canvases/carpet-cleaning.pflow:34
pflow_enums { entity: "Service", field: "Статус" }
→ ['идея', 'MVP', 'действующая']
pflow_scaffold { entity_type: "услуга", name: "чистка_премиум", write: false }
→ DSL-заготовка с placeholder'ами
```

### 3. Агент пишет файл

`services.sflow`:

```sflow
Услуга: "чистка_премиум" {
  Статус:    идея
  Реализует: ["профессиональная химчистка"]
  Цена:      18000
  Период:    месяц
  Валюта:    RUB
}
```

### 4. Агент валидирует и видит пробелы

```
pflow_validate
→ services.sflow:1 [warning] Услуга должна ссылаться на Работу через поле Работа:
→ services.sflow:1 [warning] Услуга без Сегментов
→ services.sflow:1 [warning] Услуга без Персон
```

### 5. Агент уточняет в чате (только то, чего не вывести)

> «Какую pflow:Работу закрывает эта услуга? Из существующих: «чистый ковёр после ремонта», «годовая поддержка офиса». Или новую?»

> «Сегменты — взять те же, что в Канвасе («Семьи в новостройке», «Офис-менеджеры»)? Подтвердите или укажите подмножество.»

> «Персоны: добавим типовые «Марина_квартира» (для семей) и «Сергей_офис» (для офисов), или у вас уже есть?»

### 6. Юзер отвечает односложно в чате

> Работа — «чистый ковёр после ремонта». Сегменты — оба. Персоны — твоя версия.

### 7. Агент дописывает, валидирует, останавливается

```
pflow_validate
→ canvases/carpet-cleaning.pflow:1 ⚠ снят: Канвас теперь покрыт Услугой
→ 0 errors, 0 warnings
```

И отчитывается:

> Готово. `services.sflow` обновлён, на Канвасе «Чистка ковров премиум-сегмента» снят warning «не покрыт Услугой». Открой outline (`Ctrl+Shift+O`) — Услуга 🛎 видна в списке. На Канвасе в hover теперь «реализуют 1 Услуг(и) ([«чистка_премиум»])».

### 8. PM руками — финальный визуальный осмотр

- Откроет `services.sflow`, посмотрит outline (🛎 / 👤 / 🎯 / 🤝 / 🧱 / 🎬).
- Hover на Услуге — проверит derived-секцию.
- Если что-то не нравится в формулировке Описания персоны — поправит руками.

**Время цикла**: 2–3 минуты от запроса до коммита. Без pflow тот же цикл — 30+ минут на согласование «куда писать» и «что не забыть».

## Типичные сценарии

### Сценарий: новая стратегия с нуля

> «У меня идея сервиса доставки еды премиум-класса. Помоги собрать стратегическую модель.»

Агент:
1. `pflow_scaffold` для Юнита, Сегмента, Работы, Канваса — с placeholder'ами.
2. Уточняет в чате: размер аудитории? Канал привлечения? Альтернативы какие?
3. После каждого ответа дописывает поле, валидирует, идёт дальше.
4. На выходе — связный набор файлов в `units.pflow` + `segments/` + `jobs/` + `canvases/`. `pflow_validate` чистый.

Что вы сказали в чате: 5–7 коротких ответов вместо 5–7 файлов вручную.

### Сценарий: связать стратегию и операции

> «Какие Канвасы у нас не покрыты Услугами?»

Агент:
```
pflow_validate { severity: "warning" }
→ canvases/A.pflow: ⚠ не покрыт ни одной Услугой
→ canvases/B.pflow: ⚠ не покрыт ни одной Услугой
```

> «Канвасы A и B не покрыты. Создаю Услуги-заглушки или хочешь обсудить — какие из них планируется реализовать в этом квартале?»

Дальше — диалог. Если PM говорит «B пока стратегическая гипотеза, не трогай» — агент добавит `# @format: off` или комментарий-маркер «WIP до Q2», чтобы warning не сбивал в следующий раз.

### Сценарий: записать наблюдение из интервью

> «Из интервью с Ивановой: «я медитирую в туалете, лишь бы 5 минут тишины» — подтверждает Сегмент «Офисный сотрудник на грани выгорания», прямой сигнал, источник https://t.me/burnout_ru/412»

Агент:
```
pflow_scaffold { entity_type: "сигнал", ... }   # черновик без цели — оставь Подтверждает/.. пустыми, добавь Касается:
pflow_locate { name: "Офисный сотрудник на грани выгорания", type: "Segment" }
```

Пишет:

```pflow
Сигнал: "иванова — 5 минут тишины в туалете" {
  Наблюдение:  "я медитирую в туалете на работе, лишь бы 5 минут тишины"
  Источник:    "https://t.me/burnout_ru/412"
  Категория:   пользователь
  Дата:        "2026-05-08"
  Подтверждает: [
    Сегмент."Офисный сотрудник на грани выгорания"
  ]
}
```

`pflow_validate` чистый. На Сегменте в IDE появился ✅-бейдж — без открытия файла видно, что у гипотезы прибавилось подтверждение.

### Сценарий: переименовать или удалить сущность

> «Переименуй Сегмент «Мамы-планировщицы» в «Семьи 30–45 лет с детьми».»

Агент:
```
pflow_refs { name: "Мамы-планировщицы", type: "Segment" }
→ incoming: 4 (3 Канваса + 1 Юнит)
→ outgoing: 0
```

> «Найдено 4 ссылки в 3 файлах. Переименовываю?»

Если да — агент правит во всех местах одной транзакцией. F2 в редакторе делает то же; через агента полезно когда нужна одновременная правка ещё чего-то («переименуй и в описании Юнита замени упоминание»).

Удаление — то же самое, но если incoming > 0 агент сначала спросит «куда переадресовать ссылки» или «убрать вместе с местом ссылки».

### Сценарий: аудит модели

> «Покажи где у нас пробелы — что недозаполнено, что без сигналов, что без услуг.»

```
pflow_coverage { stale_months: 3 }
→ Канвас «B»: нет signal_missing (3 поля без сигналов)
→ Сегмент «C»: signal_stale (последний сигнал 4 месяца назад)
→ Работа «D»: orphan_job (ни один Канвас не ссылается)
→ Канвас «E»: not_realized (не покрыт ни одной Услугой)
```

> «4 пробела. Какой первым? Я могу для каждого предложить заполнение или пометить как «принято к сведению».»

### Сценарий: подключить агента к существующему pflow-проекту

В корне проекта (палитра VS Code):
- **`ProductFlow: Подключить MCP-сервер к текущему проекту`** — создаст `.mcp.json`, `AGENTS.md`, `CLAUDE.md`. `.pflow`/`.sflow` файлы не трогаются.

После этого открыть проект в Claude Code или совместимом — он автоматически подхватит MCP-сервер pflow и начнёт видеть модель.

Если pflow-проекта ещё нет, есть **`ProductFlow: Инициализировать проект`** — раскатает `templates/starter/` (рабочий пример с MindApp/чисткой ковров) + `.mcp.json`. Можно сразу начать с диалога «измени стартер под мой продукт».

## Что вы получаете в IDE (для тех 20% что руками)

### Outline и breadcrumbs с эмодзи

```
🏢 MindApp                                  ← Юнит
  📦 Короткие медитации                     ← Канвас
    🔧 библиотека медитаций от 5 до 15 минут
    📡 хочу медитировать, но боюсь...        ← Сигнал

🛎 чистка_ковров_премиум                    ← Услуга
👤 Марина_квартира                          ← Персона
🎯 после ремонта квартиры                   ← Контекст
🤝 не повредим ворс и цвет                  ← Обещание
🎬 ковёр_марины_после_ремонта               ← Сценарий
🧱 своя_машина_забора                       ← Опора
```

`Ctrl+Shift+O` — быстрая навигация по сущностям. Эмодзи в outline совпадают с эмодзи в inlay-бейджах — один визуальный язык.

### Inlay-бейджи у имён

Возле каждой именованной сущности — счётчик связанных, с tooltip-списком кликабельных имён.

```
Канвас:    🏢 1 · 🔗 2 · 🛎 2          ← Юнит, Связки, реализующие Услуги
Сегмент:   📦 3 · 🏢 1 · 💼 2 · 👤 2    ← Канвасы, Юниты, Работы, Персоны
Работа:    📦 3 · 🔀 1 · 🛎 1 · 🎯 4    ← Канвасы, Switch, Услуги, Контексты
Услуга:    📦 2 · 💼 1 · 👥 1 · 🎯 4 · 🤝 5 · 👤 2 · 🧱 6 · 🎬 2
Контекст:  🛎 1 · 👤 1 · 🤝 2 · 🎬 1
Сценарий:  готов · 🛎 1 · 👤 1 · 🎯 1 · 🤝 N · 🧱 N
Опора:     актив · есть · 🛎 1 · 🎬 2
```

### Сигналы возле полей

```
Канвас: "Живые группы"  ✅✅❌
Приоритет: высокий       ❌
```

Видно, где гипотеза подкреплена, а где опровергнута. Hover → список сигналов с прыжком к каждому.

### Дружелюбные диагностики

| Что написал пользователь / агент | Что видит |
|---|---|
| Сигнал без целей (ни `Подтверждает`, ни `Опровергает`, ни `Связан`) | hint «Инбокс-сигнал: ни одного пути. Добавь цель при разборе» |
| Путь-ссылка с опечаткой в имени (`Канвас."Опечатк"`) | parser error «Could not resolve reference to TopLevelNamed named 'Опечатк'» (Langium native) |
| Путь-ссылка с правильным root, но мёртвым шагом (`VPC."X"/Предложение."NotFound"`) | validation error «Путь-ссылка не разрешается: один из шагов не найден внутри родителя» |
| `Категория: пользователь` без `Дата:` | error «Сигнал с Категория: пользователь обязан иметь поле Дата:» |
| Канвас, чьи Предложения никем не реализованы | warning «стратегическая гипотеза без операционного исполнения» |
| Услуга без `Реализует:` | warning «не видно какие Канвасы покрывает» |
| Действующая Услуга реализует Предложение со `Статус: гипотеза` | warning «непроверенное Предложение» |
| Цикл в `Зависит_от:` Компонента / в `Требует:` Зависимости / в Апгрейде | error «Циклическая зависимость» |

### F2 / F12 / Hover

- **F2** на любом имени → переименование во всех файлах workspace, включая cross-layer (svcflow ↔ pflow).
- **F12** на cross-ref → прыжок к декларации (в любом DSL).
- **Hover** на имени → markdown-карточка: header + поля + derived-секция «В этом проекте» + файл-определения. Имена в derived — кликабельные ссылки.

## Что агент использует под капотом

| MCP-tool | Когда |
|---|---|
| `pflow_list` | «какие сущности есть», холодный старт диалога |
| `pflow_context --focus name` | прицельный markdown-срез одной сущности и её соседей |
| `pflow_locate` | «где описан X» — file/uri/range для прицельного `Read` |
| `pflow_validate` | после каждой правки — проверить чистоту |
| `pflow_coverage` | аудит «где пробелы», в т.ч. cross-layer (Канвас не покрыт Услугой) |
| `pflow_refs` | impact перед переименованием/удалением |
| `pflow_signals` | «какие наблюдения у этой сущности», «опровергнутые гипотезы» |
| `pflow_jobs_map` | переиспользование Работ — где одна и та же JTBD используется в разных Канвасах |
| `pflow_enums` | допустимые значения enum-полей (без галлюцинаций) |
| `pflow_scaffold` | DSL-заготовка по типу — гарантированно валидная структура |

Подробнее — [mcp.md](mcp.md).

## Когда диалог с агентом останавливается

Агент **не** угадывает три вещи и спрашивает у вас:

1. **Содержательные смыслы** — «какая работа», «какой сегмент», «какой подход в Предложении». Это знание PM, не выводится из модели.
2. **Стратегические выборы** — «делать ли Канвас, который не покрыт услугой» (есть варнинг — но это валидный незавершённый этап). Агент пометит, не удалит.
3. **Формулировки в свободном тексте** — Описание, Ситуация, Эмоция. Агент может предложить шаблон, но окончательная версия — ваша.

Всё остальное (структура, enum-литералы, cross-refs, файл-расположение, сортировка полей) — агент решает сам, потому что у инструмента на это есть детерминированный ответ.
