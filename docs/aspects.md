# Аспекты — операционный справочник PM

Дерево сущностей в Activity Bar — **главная рабочая поверхность** продакта в ProductFlow. Это не реестр сущностей в алфавитном порядке, а **narrative-первая** карта проекта: project-обзор + страница на каждый Канвас.

Эта страница — карта аспектов с точки зрения PM: когда смотреть, какой сигнал даёт каждый узел, что с ним делать.

## Как читать дерево

```
📋 О проекте          ← общий обзор: рамки, ставки, развилки, доказательная база
📦 Канвас «<имя>»     ← страница на каждый Канвас (audience, job, switch, value, …)
```

**Бейджи на каждом узле:**
- 🔴 critical — есть проблема, которая блокирует или ломает.
- 🟡 attention — есть что подтянуть, не блокер.
- 🟢 ok — порядок.
- Цифра в badge (на иконке Activity Bar) — сколько narrative-аспектов в stale + missing статусе саммари.

**Drill-down:** клик по узлу раскрывает blocks; клик по item ведёт **в файл** на точную строку. Tooltip на узле — markdown с пояснением «почему важно».

## Health-чекеры (11): флаги модели

Параллельно narrative-аспектам builder проверяет 11 health-чекеров и проецирует findings inline в блоки соответствующих узлов:

- `health.unfounded` — декларации без Сигналов (узлы под твёрдыми Предпосылками исключены).
- `health.orphans` — сущности без входящих ссылок (мусор от прошлого или забытое).
- `health.broken-refs` — сломанные путь-ссылки в Сигналах.
- `health.canvas-skeleton` — Канвас без VPC, VPC без Предложения, Предложение без реализующей Услуги.
- `health.empty-fields` — обязательные поля пустые (Сегмент без Размера, Услуга без Обещаний).
- `health.coverage` — Сегменты без VPC, Работы без Предложения, Ситуации без обслуживающего Канваса.
- `health.unit-economics` — Канал без CAC/LTV; LTV/CAC < 3 или payback > 12 мес.
- `health.stale-signals` — Сигналы старше 6 мес (🟡) или старше года (🔴).
- `health.vpc-redundancy` — несколько VPC в одном Канвасе с одинаковым именем Предложения — кандидат на объединение.
- + 2 stub-чекера (`health.disputed`, `health.summaries-coverage`) — резерв на следующие итерации.

## Ритуалы PM

Не нужно смотреть всё каждый день. Раскладка по частоте:

**Каждое утро (5 мин):**
- Health-флаги в дереве — что красное со вчера?
- Чекеры `health.*` в секции 🩺 Здоровье (Реестр) — топ-проблемы.

**Раз в неделю (15 мин):**
- `health.stale-signals` — что устаревает.
- `narr.project.evidence` (если стейл) — обновить картину доказательной базы.
- `narr.project.decisions` — есть ли новые развилки.

**Перед спринтом / квартальным review (45 мин):**
- `narr.project.bets` — где мы по метрикам-ставкам.
- `narr.project.portfolio` — как меняется конфигурация Юнитов.
- `health.coverage` + `health.unit-economics` — операционные слабые места.

**На стратсессии (2-3 часа):**
- `narr.project.frames` — Премиссы, в каких рамках действуем.
- `narr.project.decisions` — какие развилки прошли, какие открыты.
- `narr.project.evidence` — где модель крепко, где на вере.
- Canvas-страницы по очереди — глубокий разбор каждого продукта.

**Для онбординга нового PM/инвестора/партнёра (30 мин):**
- `narr.project.intro` → 12 project-аспектов по порядку → страницы каждого Канваса. Это устный «тур по продукту» через готовые narrative-саммари.

## Narrative-саммари

На каждый narrative-аспект (project или canvas) можно держать LLM-сгенерированный человеко-читаемый абзац — для маркетолога, инвестора, нового участника. Хранилище — `.pflow/summaries-v2.jsonl` (ключ — пара `(aspect_id, scope)`).

**Жизненный цикл:**
- LSP считает `input_hash` структурного контекста при каждом валидном билде.
- Устаревшие саммари получают ⚠-бейдж в дереве + Information-диагностику в Problems panel.
- Регенерация — через цикл MCP `pflow_aspect_v2_status` → `pflow_aspect_v2_context` → `pflow_aspect_v2_save`.

Файл редактировать руками не нужно: ручная правка останется fresh по hash до следующего изменения модели, потом станет stale молча. Правильный путь — через агента.
