# DSL Guide

В проекте два DSL, оба на русском, UTF-8:

- **pflow** (`.pflow`) — стратегический слой: Business Model Canvas (с BMC-блоками Партнёры/Ресурсы/Активности/Отношения), **VPC** (Value Proposition Canvas — per-segment ценностное предложение: Сегмент → Работы → Альтернативы → УТП → Предложения), JTBD, Customer Journey (Switch), портфельная архитектура (Юниты/Связки/Петли), Компоненты, Альтернативы, Результаты (ODI Outcomes — метрики-ставки), Предпосылки (scope-ограничения и founder's bets), Развилки (точки стратегического выбора с историей), Ситуации (GTM-триггеры: момент + ЛПР + Работа), top-level Сигналы с путь-ссылками.
- **svcflow** (`.sflow`) — операционный слой: Услуги, Обещания, Персоны, Контексты, Сценарии, Опоры, Апгрейды, Зависимости, Продукты, Треки, Портфели.

> **Справочник по каждой сущности** — роль, как её назвать (паттерн имени + ✓/✗), что писать в поля, антипаттерны — в [dsl-reference.md](dsl-reference.md) (autogen из брифов, `npm run gen:reference`). Тот же контент по запросу — MCP-tool `pflow_guide { entity_type }`.

Оба живут в одном воркспейсе, обмениваются cross-layer ссылками: `Service.Реализует:` → `pflow:Предложение` (резолвится в `VPCSolution` — Предложение внутри VPC), `Service.Сегменты:` → `pflow:Сегмент`, `Service.Состав:` → `pflow:Компонент`, `Persona.Сегмент:` → `pflow:Сегмент`, `Pillar.Обеспечивает:` → `pflow:Ресурс`, `SvcContext.Альтернативы:` → `pflow:Альтернатива`, `SvcContext.Ситуация:` → `pflow:Ситуация` и т.д. Формат путь-ссылок Сигнала описан ниже, в разделе про Сигналы.

## Карта сущностей через продуктовые вопросы

Каждая сущность отвечает на конкретный продуктовый вопрос. Грамматика валидирует, что ответ полный.

### Стратегический слой (pflow)

| Вопрос | Сущность | Что проверяет |
|---|---|---|
| **Кто наш пользователь?** | Сегмент | размер аудитории, ранние адопторы; для B2B опционально Выручка/Стадия/Платёжеспособность/ЛПР |
| **Зачем ему это?** | Работа (JTBD) | каноническая структура `Когда / Хочу / Чтобы / Но` + тип `функциональный/эмоциональный/социальный`; формулировка без упоминания продукта |
| **Откуда переходит, что мешает?** | Переключение | 5 обязательных секций: Толчок, Притяжение, Тревога, Привычка (Альтернативы → top-level Альтернатива), Хронология. Опциональное поле `Ситуация:` связывает Switch с моментом возникновения боли |
| **Что мы предлагаем?** | Канвас (BMC) | бизнес-модель продукта: `VPC: [...]` (массив ссылок на per-segment ценностные предложения), Каналы, Метрики, Доходы, Расходы + 4 BMC-блока (Партнёры/Ресурсы/Активности/Отношения) + `Преимущество:` (defensible moat). `Ситуации:` — GTM-сценарии, в которых работает Канвас. Сегменты и Предложения живут в VPC |
| **Чем мы это решим?** | VPC + Предложение | **VPC** (Value Proposition Canvas, top-level, per-segment): `Сегмент:` + `Работы: [...]` + `Альтернативы: [...]` + `УТП:` + одно или несколько вложенных Предложений. **Предложение (внутри VPC)**: `Решает:` ссылка на Работу; `Подход`, `Статус`, `Покрытие`. Связь с Развилкой одностороння — Развилка декларирует область влияния через `Развилка.Влияет_на: [VPC]`; на Предложении inline-hint показывает Развилку через reverse-index. Корень для cross-layer привязки `Service.Реализует` (резолвится в `VPCSolution`) |
| **Как доставим?** | Канал (внутри Канваса) | `Тип:` (входящий/исходящий/вирусный/партнёрский) + `Стоимость:` + опц. unit-economics `CAC:` / `LTV:` / `Конверсия:` (INT, %); LTV/CAC ratio считается в `operations.economics` |
| **Где тратим?** | Расходы (внутри Канваса) | `Сумма:` + `Валюта:` + `Период:`; тело опционально (категорийные статьи без чисел); учитывается в P&L Канваса |
| **Как зарабатываем?** | Доход (внутри Канваса) | `Модель:` (подписка/реклама/транзакция/...) + точечная `Цель:` (целое число) + `Валюта:` + опц. `Период:` |
| **Откуда мы знаем?** | Сигнал | top-level; `Наблюдение`, `Источник`, `Категория` (кабинет/эксперт/пользователь/продажа/метрика), `Дата` (обязательна для кат. эксперт+); цели — через путь-ссылку в `Подтверждает` / `Опровергает` / `Связан` |
| **Как продукты связаны?** | Юнит | декларация портфеля + `Назначение` (маркетинговый/коммерческий/продуктовый) + `Статус` (текущий/перспективный/закрытый) + `Запуск_при:` + опц. `Валюта:` (default для всех денежных значений в Канвасах Юнита) + `Ситуации:` — GTM-сценарии портфельного уровня |
| **Как усиливают друг друга?** | Связка + Петля | апселл/пакет и механизм возврата с явными триггерами |
| **С кем сотрудничаем?** | Партнёр | роль (стратегический/канал_доступа/...) + Доступ_к Сегментам + Тип_договорённости + Статус |
| **На каких ресурсах держимся?** | Ресурс | ключевой актив BMC; интеллектуальный/технический/человеческий/социальный/финансовый |
| **Что мы делаем регулярно?** | Активность | макропроцесс BMC; Регулярность + Поддерживает: → Ресурс |
| **Из каких модулей собираем?** | Компонент | модуль Услуги (процесс/артефакт/продукт/интеграция/агент/библиотека); Семейство + Уровень + Зависит_от |
| **Что клиент использует вместо нас?** | Альтернатива | top-level; ссылается из `VPC.Альтернативы:` (рынок vs наш продукт по сегменту), `Привычка.Альтернативы:` (Switch), `SvcContext.Альтернативы:` |
| **Какие у нас рамки?** | Предпосылка | scope-ограничения, founder's bets и зафиксированные пивоты; `Тип:` (ставка/ограничение/компетенция) + `Причина:` + `Пересмотр:` (твёрдая/мягкая/на_срок) + `Дата:` + `Влияет_на:` → Refable[]. Твёрдые Предпосылки с заполненным `Влияет_на:` защищают узлы от warning `state.unfounded`; мягкие и на_срок — нет. Пустое `Влияет_на:` обнуляет защиту: Премисса никого не покрывает |
| **Какие развилки мы прошли?** | Развилка | точка стратегического выбора с историей; `Вопрос:` + `Варианты:` + `Выбрано:` + `Причина:` + `Пересмотреть_если:` + `Статус:` (открыта/решена) + `Дата:` + `Влияет_на:` → Refable[]. Не путать с Альтернативой: Альтернатива — что делает рынок, Развилка — что рассматривали внутри команды |
| **В каких ситуациях возникает боль?** | Ситуация | GTM-атом: `Триггер` → `ЛПР` (Сегменты) → `Работа` + `Срочность` (низкая/средняя/высокая/критическая) + `Неясно`; одна Ситуация — один лендинг/outbound-кейс. Reverse-index показывает, сколько Канвасов её обслуживают (0 = продуктовый пробел) |
| **Какие метрики хотим сдвинуть?** | Результат (ODI Outcome) | гипотеза о метрике в формате ODI: `Направление` (уменьшить/увеличить/избежать) + `Что` + `Цель`; опц. `Работа:` для derived-связи Работа ↔ Результат. На Outcome ссылаются `VPC.ERRC.Поднять/Создать` (наши ставки в Blue Ocean анализе) и `svcflow:Обещание.Закрывает:`. Защищается твёрдой Премиссой — иначе попадает в `state.unfounded` до прихода Сигналов |

> Эта таблица — **источник формулировок** для дерева сущностей в Activity Bar (контейнер ProductFlow → view «Сущности»). Каждая строка соответствует записи в catalog'е с заполненными `question` + `treeOrder`; smoke-services валит сборку при пропуске. Порядок строк = порядок групп в дереве.
>
> **Narrative-саммари по проекту и канвасам.** На каждый narrative-аспект (project + per-canvas) можно держать человеко-читаемый абзац (LLM-обзор «у нас X сегментов, главный — Y, …»). Хранилище — `.pflow/summaries-v2.jsonl` в корне проекта (по строке JSON на пару `(aspect_id, scope)`). Жизненный цикл: агент через MCP дёргает `pflow_aspect_v2_status` → видит что устарело → запрашивает `pflow_aspect_v2_context { aspect_id, scope }` → генерирует абзац → сохраняет через `pflow_aspect_v2_save`. LSP считает `sha256` структурного контекста при каждом валидном билде; устаревшие саммари получают ⚠-бейдж в дереве + Information-диагностику в Problems panel. Файл редактировать руками не нужно: если поправил абзац напрямую — он останется fresh по hash, но при следующем изменении модели снова станет stale; правильный путь — генерация через агента.

### Операционный слой (svcflow)

| Вопрос | Сущность | Что проверяет |
|---|---|---|
| **Что мы продаём?** | Услуга | Реализует Предложения pflow, Сегменты, Персоны, Контексты, Обещания, Опоры, Срок, Цена |
| **Что клиент получает?** | Обещание | Формулировка + Кому (персоны) |
| **Кто конкретно покупает?** | Персона | Сегмент (cross-layer на pflow) + что отличает |
| **В какой ситуации обращается?** | Контекст | Работа (pflow) + Персоны + Ситуация/Эмоция/Триггер + ключевые/поддерживающие Обещания + опц. `Приоритет:` (низкий/средний/высокий/критический — куда инвестируем) и `Сила:` (низкая/средняя/высокая — насколько реален спрос; ортогональна Приоритету). Действующая Услуга на Контексте с `Сила: низкая` → conflict в `state.disputed` |
| **Как услуга работает?** | Сценарий | Услуга × Персона × Контекст; Дано/Когда/Тогда; Статус черновик→готов |
| **На чём держится обещание?** | Опора | Тип (актив/процесс/методология/социальная) + Категория + Состояние (есть/в_работе/нет) + `Обеспечивает:` → pflow:Ресурс |
| **Куда клиент переходит дальше?** | Апгрейд | Из → В + Условие + опц. Конверсия (воронка услуг) |
| **Что должно быть готово?** | Зависимость | прецеквизит/совместимость/исключение между Услугами |
| **Как упакованы услуги?** | Продукт | аналог pflow:Канвас на операционном слое: упаковка Услуг под одним брендом. `Основная:` + `Уровни:` (tiers) + `Опции:` (add-on-ы); `Канвас:` → pflow:Канвас, который этот Продукт операционализирует |
| **Какой путь проходит сегмент?** | Трек | маршрут Сегмента через Продукт. `Этапы:` — упорядоченный список Услуг; `Апгрейды:` — ссылки на существующие `Апгрейд:` (переходы). Валидатор требует, чтобы Апгрейд.Из/В лежали в Этапы: |
| **Как продукты и треки сгруппированы?** | Портфель | аналог pflow:Юнит на операционном слое: иерархия Продуктов и Треков одной командной единицы. `Юнит:` → pflow:Юнит |

## Грамматика pflow

### Сегмент

```pflow
Сегмент: "Офисный сотрудник на грани выгорания" {
  Описание: "работает в режиме дедлайнов, хронически не высыпается"
  Размер:   8000000
  Ранние:   "подписчики Telegram-каналов про осознанность и выгорание"
}
```

### Работа (JTBD)

Каноническая форма Алана Клемента вшита в грамматику:

```pflow
Работа: "успокоиться за 10 минут на рабочем месте" {
  Когда:    "после трёх митингов подряд, до созвона 15 минут, голова гудит"
  Хочу:     "сбросить напряжение, не отрываясь от рабочего дня"
  Чтобы:    "продолжить работать сосредоточенно и не сорваться на коллегах"
  Но:       "коллеги не медитируют, делать это открыто странно"
  Тип:      эмоциональный
  Сегменты: ["Офисный сотрудник на грани выгорания"]
}
```

Если в `Хочу:` или `Чтобы:` появляется слово «приложение» / «фича» / «алгоритм» — это уже не Работа, а Предложение.

### Канвас (Business Model Canvas) + VPC

Канвас описывает бизнес-модель продукта (каналы, P&L, BMC-блоки). Ценностное
предложение для каждого Сегмента живёт в отдельной сущности **VPC** (Value
Proposition Canvas), на которые Канвас ссылается через `VPC: [...]`. Одна VPC
≈ один лендинг для одного Сегмента; в одном Канвасе может быть несколько VPC,
если продукт обращается к разным аудиториям.

```pflow
VPC: "Офисные сотрудники — короткие медитации" {
  Сегмент:      "Офисный сотрудник на грани выгорания"
  Работы:       ["успокоиться за 10 минут на рабочем месте"]
  Альтернативы: ["YouTube-ролики", "музыка в наушниках", "выход на улицу"]
  УТП:          "медитация за 10 минут — без подготовки, коврика и особых условий"

  Предложение: "библиотека медитаций от 5 до 15 минут" {
    Решает:   "успокоиться за 10 минут на рабочем месте"
    Подход:   "5/10/15-минутные сессии без подготовки"
    Статус:   работает
    Покрытие: частичное
  }
}

Канвас: "Короткие медитации" {
  VPC:      ["Офисные сотрудники — короткие медитации"]
  Ситуации: ["После_напряжённых_митингов", "Перед_важным_разговором"]  # GTM-сценарии

  Канал: "SEO и блог об осознанности" {
    Тип:       входящий
    Стоимость: "80000 RUB/мес"
  }

  Расходы: "запись аудио-контента" { Сумма: 150000  Валюта: RUB  Период: месяц }
  Доход:   "конверсия в подписку"  { Модель: freemium  Цель: 490  Валюта: RUB }
}
```

**Разделение ответственности.** VPC отвечает на «что предлагаем под этот Сегмент»
(один Сегмент → одна VPC → его Работы / Альтернативы / УТП / Предложения). Канвас
описывает бизнес-модель вокруг этого предложения: Каналы, P&L, BMC-блоки,
Преимущество, привязка к Ситуациям. Один Канвас может ссылаться на несколько VPC,
если продукт работает с разными аудиториями.

### Юнит — портфельная декларация

```pflow
Юнит: "MindApp" {
  Канвасы:      ["Короткие медитации", "Личная программа", "Живые группы"]
  Сегменты:     ["Офисный сотрудник на грани выгорания"]
  Переключения: ["переход с YouTube на приложение"]
  Ситуации:     ["После_напряжённых_митингов", "Перед_важным_разговором"]  # портфельный GTM-взгляд

  Валюта: RUB
  Метрики: {
    Выручка_месяц:         10000000   # INT, в Валюте Юнита
    Расходы_фиксированные: 3500000
    AOV:                   850
    LTV:                   7400
    Клиентов_месяц:        5000
  }
}
```

Все поля Метрик — целые числа, валюта берётся из `Валюта:` Юнита. Если хочется диапазона — это сигнал что нужен отдельный Сигнал с источником, а не fuzzy-значение в Метриках.

Валидаторы:
1. Канвас в нескольких Юнитах → ошибка (двойной учёт P&L).
2. Сегмент в Юните без обслуживающего Канваса → «декларация без реализации».
3. Канвас тянет Сегмент не из Юнита-владельца → «реализация без декларации».
4. Канвас не покрыт ни одной Услугой (через `Service.Реализует`) → «стратегическая гипотеза без операционного исполнения».

### Переключение (Demand-Side Sales)

Switch Triggers — структурированная сущность из 5 обязательных секций:

```pflow
Переключение: "переход с YouTube на приложение" {
  Работа:    "успокоиться за 10 минут прямо на рабочем месте"
  Ситуация:  "После_напряжённых_митингов"  # опц.: момент, когда боль активируется

  Толчок: {
    Проблема: "включил ролик на 10 минут, вышел через час"
    Момент:   "ночь перед важным совещанием"
  }

  Притяжение: {
    Привлекает: "только медитация, без отвлечений"
    Обещание:   "ровно 10 минут и всё"
  }

  Тревога: {
    Про_новое:   "вдруг не зайдёт и деньги выброшены"
    Про_процесс: "непонятно как отменить подписку"
  }

  Привычка: {
    Альтернативы: ["YouTube-ролики", "музыка в наушниках"]
    Норма_среды:  "коллеги не медитируют, делать это открыто странно"
  }

  Хронология: {
    Первая_мысль:    "заметил, что от YouTube ещё сложнее оторваться"
    Пассивный_поиск: "видел рекламу медитационных приложений, не кликал"
    Активный_поиск:  "сравнил три приложения в App Store"
    Решение:         "скачал по рекомендации из рабочего чата"
    Первый_опыт:     "5-минутная медитация перед сном помогла заснуть"
  }
}
```

Каждая секция обязательна — структура давит на конкретику.

### Связка и Петля

```pflow
Связка: "путь от бесплатного к подписке" {
  Тип:        апселл
  База:       "Короткие медитации"
  Дополнение: "Личная программа"
  Условие:    "после 7 бесплатных сессий — 21-дневный курс со скидкой 30%"
}

Петля: "возврат через живую группу" {
  Из:       "Короткие медитации"
  В:        "Живые группы"
  Триггер:  "пользователь не открывал приложение 14 дней"
  Канал:    "SEO и блог об осознанности"      # ссылка на Канал из Канваса
  Усиление: "первое посещение группы бесплатно"
}
```

`Тип:` Связки — `пакет` / `апселл` / `зависимость`. Петля — асинхронная (с триггером и каналом возврата).

### Ситуация — GTM-триггер

Атомарный кейс: в какой момент, у кого и с какой Работой боль активна настолько, чтобы перейти к покупке. Одна Ситуация = один лендинг / outbound-месседж / обещание срока.

```pflow
Ситуация: "После_напряжённых_митингов" {
  Описание:  "После серии митингов подряд голова гудит, концентрация падает, до следующего созвона 15 минут"
  Триггер:   "Три митинга подряд закончились, в календаре пауза 15 минут"
  ЛПР:       [Сегмент."Офисный сотрудник на грани выгорания"]
  Работа:    "успокоиться за 10 минут прямо на рабочем месте"
  Срочность: высокая
  Неясно:    "Сколько таких пауз в день? Гипотеза — 2–3, но не измерено"
}
```

`Срочность:` — `низкая` / `средняя` / `высокая` / `критическая`. `ЛПР:` — массив ссылок на top-level `Сегмент`. `Неясно:` — необязательное текстовое поле для открытых гипотез.

Reverse-index в hover Ситуации показывает:
- сколько Канвасов ссылаются через `Ситуации:` (0 = пробел: ситуация есть, но продукта под неё нет)
- сколько Юнитов включают в `Ситуации:` (портфельный взгляд)
- сколько Переключений ссылаются через `Ситуация:` (откуда приходят клиенты в этот момент)
- сколько svcflow-Контекстов реализуют эту Ситуацию через cross-layer `SvcContext.Ситуация:`

### Предпосылка — scope-ограничение

Осознанные ставки и ограничения, которые не валидируются рынком, а задают рамки. Сюда же попадают зафиксированные пивоты: смена типа клиента, сегмента, географии, продуктовой категории — всё, что обесценивает часть собранных данных, закрепляется новой Премиссой с `Тип: ставка, Пересмотр: твёрдая`. Твёрдые Премиссы защищают узлы от warning `state.unfounded` («декларация без опоры»).

```pflow
Предпосылка: "Только_премиум_сегмент" {
  Тип:       ставка
  Причина:   "Эконом-сегмент требует другой себестоимости; распыляться при команде 4 человека невозможно"
  Пересмотр: твёрдая
  Источник:  "founder"
  Дата:      "2025-03-15"
  Влияет_на: [
    Сегмент."Офисный сотрудник на грани выгорания"
  ]
}
```

`Тип:` — `ставка` / `ограничение` / `компетенция`. `Пересмотр:` — `твёрдая` (не пересматривается без pivot) / `мягкая` (при новых данных) / `на_срок` (до конкретной даты). Только `твёрдая` даёт защиту от `state.unfounded`. `Влияет_на:` — массив ссылок типа `Refable` (Канвас, Сегмент, Работа, Юнит, VPC, Результат и др., но не Предпосылка/Развилка/Ситуация/Сигнал). Без заполненного `Влияет_на:` Премисса никого не покрывает — защита от `state.unfounded` не срабатывает.

### Развилка — история выбора

Документирует, что рассматривали внутри команды, что выбрали и при каких условиях возвращаться к вопросу. Применима, когда все варианты совместимы с уже собранными данными — это внутрикомандный выбор реализации. Если хотя бы один вариант обесценивает собранное (меняет тип клиента, Сегмент, географию, ценовой класс, канал, формат работы) — это пивот, и фиксируется он не Развилкой, а Премиссой `Тип: ставка, Пересмотр: твёрдая`. Не путать с `Альтернативой`: Альтернатива — что делает рынок, Развилка — внутренний выбор команды.

```pflow
Развилка: "Формат_контента_2025" {
  Вопрос:            "Аудио или видео для медитаций?"
  Варианты:          ["аудио_без_видео", "видео_инструктор", "анимация_дыхание"]
  Выбрано:           "аудио_без_видео"
  Причина:           "Видео требует студии и не подходит для фонового воспроизведения; 8 из 10 тест-пользователей использовали приложение с закрытым экраном"
  Пересмотреть_если: "Конкуренты с видео займут >30% рынка ИЛИ метрика удержания аудио упадёт <60% через 30 дней"
  Статус:            решена
  Дата:              "2025-02-10"
  Влияет_на:         [VPC."Офисные сотрудники — короткие медитации"]
}
```

`Статус:` — `открыта` (активно обсуждается) / `решена` (зафиксировано). Связь Развилка ↔ Предложение одностороння: Развилка декларирует область влияния через `Влияет_на:` (включая VPC, в котором живут затронутые Предложения); на Предложении inline-hint показывает Развилки через reverse-index. Симметрично Премиссе — обратной ссылки `Предложение → Развилка` как поля нет, чтобы не плодить двусторонние декларации.

### Результат (ODI Outcome) + ERRC внутри VPC

`Результат:` — гипотеза о метрике в формате [Outcome-Driven Innovation](https://strategyn.com/outcome-driven-innovation-process/) Тони Ульвика: «уменьшить/увеличить/избежать <что> относительно <цели>». В отличие от Работы (вечная потребность клиента), Результат — это **наша ставка** на конкретный замеряемый исход.

```pflow
Результат: "Скорость_первого_ответа" {
  Работа:      "Перерастание ручной обработки заявок"  # optional
  Направление: уменьшить                                 # уменьшить / увеличить / избежать
  Что:         "время от заявки клиента до первого ответа"
  Цель:        "< 30 минут"
}
```

Связь `Работа → Результат` — derived через reverse-index: поля `Работа.Результаты:` нет, на Работе inlay показывает все Outcome'ы, ссылающиеся на неё через `Результат.Работа:`. Сделано так, чтобы избежать циклической зависимости между грамматиками `job.langium` и `outcome.langium`.

**Эпистемический статус.** Outcome — гипотеза. Пока на него не указал `Сигнал`, он не подтверждён внешним evidence. **Твёрдая Предпосылка** `Влияет_на: ["Скорость_первого_ответа"]` защищает Outcome от попадания в `state.unfounded` — это осознанная ставка фаундера, а не забытый узел.

**ERRC внутри VPC.** Outcome'ы — мишени для двух квадрантов [Blue Ocean Strategy](https://www.blueoceanstrategy.com/tools/four-actions-framework/) внутри `VPC:`:

```pflow
VPC: "Sales Flow Sprint B2B" {
  Сегмент:      "Руководитель растущей компании"
  Альтернативы: ["Excel", "Самостоятельное_внедрение"]
  УТП:          "За 14 дней без потери лидов"

  ERRC: {
    Убрать:  ["Длительный цикл консалтинга"]        # свободные строки — атрибуты индустрии
    Снизить: ["Порог входа"]                         # свободные строки — атрибуты индустрии
    Поднять: ["Скорость_первого_ответа"]            # [Outcome:STRING] — наши ODI-ставки
    Создать: ["Прозрачность_воронки"]               # [Outcome:STRING] — наши ODI-ставки
  }
}
```

Разделение `Убрать/Снизить` (свободные строки) vs `Поднять/Создать` (cross-ref на Outcome) намеренное: первые описывают **что мы перестаём делать как индустрия**, вторые — **на какие метрики мы ставим**. Outcome — первоклассный узел, его нужно отдельно сформулировать в ODI-формате и защитить Премиссой.

### Сигнал — доказательная база

**Только top-level.** Цели задаются через **структурный путь-ссылку** в одном из трёх массивов:

- `Подтверждает: [...]` — наблюдение подкрепляет тезис.
- `Опровергает:  [...]` — наблюдение опровергает.
- `Связан:       [...]` — нейтральная связь (пока разбираемся).

Противоречие — пара `Сигнал.Подтверждает [X]` + `Сигнал.Опровергает [X]` на одну цель: новой сущности под это не вводится, противоречия вычисляются по индексу.

Формат пути — `Тип."имя"/Тип."имя"/Поле["элемент"]`, грамматика и семантика:

- `Работа."имя"`                                       — top-level сущность.
- `VPC."X"/Предложение."Y"`                                — именованная дочерняя.
- `VPC."X"/Предложение."Y"/Статус`                         — скалярное поле.
- `VPC."X"/Альтернативы["имя"]`                        — элемент массива.

```pflow
Сигнал: "участники групп чаще скачивают приложение" {
  Наблюдение:  "участники групп в 3 раза чаще скачивают приложение после офлайн-занятия"
  Источник:    "https://example.com/cohort-analysis-2025"
  Категория:   метрика
  Дата:        "2025-04-02"
  Подтверждает: [
    Канвас."Живые группы",
    Работа."успокоиться за 10 минут"
  ]
}

Сигнал: "страх выглядеть странно при медитации" {
  Наблюдение: "хочу медитировать, но боюсь выглядеть странно"
  Источник:   "https://t.me/burnout_ru/531"
  Категория:  пользователь
  Дата:       "2025-11-10"
  Опровергает: [
    VPC."Офисные сотрудники — короткие медитации"/Предложение."библиотека медитаций от 5 до 15 минут"/Статус
  ]
}
```

`Категория:` — `пользователь` / `метрика` / `кабинет` / `эксперт` / `продажа`. Категории `эксперт/пользователь/продажа/метрика` обязаны иметь `Дата:`. Первый сегмент пути резолвится Langium cross-ref'ом (нативный F12/rename/completion), вложенные шаги — через `resolvePathRef`; невалидный путь даёт parse error на этапе ввода или validation error «один из шагов не найден».

## Грамматика svcflow

### Услуга — корень операционной модели

```sflow
Услуга: "чистка_ковров_премиум" {
  Статус:    действующая
  Работа:    "чистый ковёр после ремонта"             # cross-layer → pflow:Работа
  Сегменты:  ["владельцы квартир со средним+ доходом"] # cross-layer → pflow:Сегмент[]
  Персоны:   ["Марина_квартира", "Сергей_офис"]
  Контексты: ["после ремонта квартиры", "перед приходом гостей"]
  Результат: "ковёр чистый, без запаха, не повреждён"
  Обещания:  ["не повредим ворс и цвет", "забираем через час после звонка"]
  Реализует: ["профессиональная химчистка"]            # cross-layer → pflow:Предложение[]
  Опоры:     ["своя_машина_забора", "стирочная_машина_karcher"]
  Срок:      "от 24 часов"
  Цена:      18000              # INT в Валюте
  Период:    месяц              # месяц / квартал / год / разово
  Валюта:    RUB                # RUB / USD / EUR
}
```

`Статус:` — `идея` / `MVP` / `действующая`. `Реализует:` — связь со стратегией: какие Канвасы (через Предложения) покрывает эта Услуга. `Цена:` сверяется с `pflow.Канвас.Доход.Цель` в `operations.economics` (cross-layer reconciliation).

### Обещание — что клиент получает

```sflow
Обещание: "не повредим ворс и цвет" {
  Формулировка: "до чистки тест на скрытом участке, при риске — звоним и согласуем"
  Кому:         ["Марина_квартира", "Сергей_офис"]
}
```

### Персона — типаж клиента

```sflow
Персона: "Марина_квартира" {
  Сегмент:  "владельцы квартир со средним+ доходом"   # cross-layer → pflow:Сегмент
  Описание: "женщина 35–55, своя квартира, ковёр — часть интерьера"
}
```

### Контекст — ситуация обращения

Главный мост к маркетингу: каждый Контекст = отдельный лендинг с подсветкой ключевых обещаний.

```sflow
Контекст: "после ремонта квартиры" {
  Работа:       "чистый ковёр после ремонта"          # cross-layer → pflow:Работа
  Персоны:      ["Марина_квартира"]
  Ситуация:     "После_ремонта_квартиры"              # cross-layer → pflow:Ситуация (структурный ref)
  Эмоция:       "досада и лёгкая паника — ковёр недешёвый"
  Триггер:      "момент разворачивания ковра после окончания работ"
  Что_важно:    ["удалить специфичные строительные загрязнения"]
  Что_не_важно: ["скорость", "детальная отчётность"]
  Обещания: [
    "не повредим ворс и цвет"        -> ключевое
    "видишь весь процесс через камеру" -> ключевое
  ]
  Каналы:       ["SEO и блог об осознанности"]    # массив ссылок на Каналы из Канвасов
  Альтернативы: ["выбросить и купить новый"]      # массив ссылок на top-level Альтернатива
}
```

`Обещания` помечаются уровнем (`ключевое` / `поддерживающее`) — это управляет приоритетом в маркетинговом сообщении.

### Сценарий — прозрачная механика

Услуга × Персона × Контекст. Дано/Когда/Тогда + Статус.

```sflow
Сценарий: "ковёр_марины_после_ремонта" {
  Услуга:     "чистка_ковров_премиум"
  Персона:    "Марина_квартира"
  Контекст:   "после ремонта квартиры"
  Показывает: ["не повредим ворс и цвет", "видишь весь процесс через камеру"]
  Статус:     готов
  Дано: [
    "клиент позвонил после ремонта",
    "ковёр в стороне, в комнате уборка"
  ]
  Когда: [
    "забор в течение 60 минут",
    "тест на цветостойкость на скрытом участке",
    "клиент видит процесс через камеру в цеху"
  ]
  Тогда: [
    "ковёр чистый, без запаха",
    "доставка через 24 часа"
  ]
  Опоры: ["своя_машина_забора", "тест_на_цветостойкость", "камера_в_цехе"]
}
```

`Статус:` — `черновик` / `готов`. Готовый сценарий должен покрывать все ключевые Обещания Контекста для Персоны (валидатор).

### Опора — на чём держится обещание

```sflow
Опора: "тест_на_цветостойкость" {
  Тип:        процесс
  Состояние:  есть
  Описание:   "перед чисткой проверяем реакцию ткани на скрытом участке"
  Стоимость:  "5 минут на ковёр, входит в стандарт"
}
```

`Тип:` — `актив` / `процесс` / `методология` / `социальная`. `Состояние:` — `есть` / `в_работе` / `нет`. Если действующая Услуга использует Опору в состоянии `нет` — валидатор предупреждает.

### Продуктовая линейка: Продукт / Трек / Портфель

Три top-level сущности svcflow для упаковки нескольких Услуг под одним продуктовым предложением. Семантически соответствуют pflow-сущностям: **Продукт ↔ Канвас** (упаковка предложения), **Портфель ↔ Юнит** (командная единица). **Трек** — маршрут конкретного Сегмента через Продукт.

```sflow
Продукт: "Премиум B2C-линейка" {
  Канвас:   "После ремонта (B2C)"               # → pflow:Канвас, который этот Продукт операционализирует
  Основная: "чистка_ковров_премиум"             # точка входа сегмента
  Уровни:   ["чистка_ковров_премиум", "экспресс_чистка_24ч"]   # tiers
  Опции:    ["годовое_обслуживание"]            # add-on-ы
}

Трек: "B2C онбординг" {
  Продукт:  "Премиум B2C-линейка"
  Сегмент:  "Владелец премиум-квартиры"          # → pflow:Сегмент
  Этапы:    ["чистка_ковров_премиум", "экспресс_чистка_24ч", "годовое_обслуживание"]
  Апгрейды: ["стандарт → экспресс 24ч", "стандарт → годовое обслуживание"]
}

Портфель: "Премиум химчистка" {
  Юнит:     "Премиум"                           # → pflow:Юнит
  Продукты: ["Премиум B2C-линейка"]
  Треки:    ["B2C онбординг"]
}
```

**Трек.Апгрейды** — переходы между этапами выражены через ссылки на существующие `Апгрейд:` (не inline-FSM). Это сохраняет Апгрейд как единственный источник правды о попарном переходе (`Из:` → `В:` + `Условие:` + `Конверсия:`). Валидатор `svc-track-validator` требует, чтобы у каждого Апгрейда из массива `Апгрейды:` поля `Из:` и `В:` ссылались на услуги, лежащие в `Этапы:` Трека — иначе переход «висит» в воздухе (warning `pflow.track.upgrade-off-steps`).

## Cross-layer связи

### Что декларируется явно

| Из | В | Поле |
|---|---|---|
| `Service` | `pflow:Job` | `Работа:` |
| `Service` | `pflow:Segment[]` | `Сегменты:` |
| `Service` | `pflow:Solution[]` | `Реализует:` — резолвится в `VPCSolution` (Предложение внутри VPC) |
| `Service` | `pflow:Component[]` | `Состав:` — модули, из которых собрана услуга |
| `Persona` | `pflow:Segment` | `Сегмент:` |
| `SvcContext` | `pflow:Job` | `Работа:` |
| `SvcContext` | `pflow:Situation` | `Ситуация:` — структурный ref, даёт reverse-index «эта Ситуация реализуется N Контекстами» |
| `SvcContext` | `pflow:Channel[]` | `Каналы:` — где клиент в этом контексте находит услугу |
| `SvcContext` | `pflow:Alternative[]` | `Альтернативы:` — что клиент мог бы использовать вместо нас |
| `SvcPromise` | `pflow:Outcome[]` | `Закрывает:` — ODI-исходы, которые закрывает это обещание |
| `SvcPromise` | `pflow:Resource[]` | `Инвариант:` — ресурсы, на которых держится выполнимость |
| `Pillar` | `pflow:Resource[]` | `Обеспечивает:` — ресурсы, которые обеспечивает эта Опора |
| `SvcProduct` | `pflow:Canvas` | `Канвас:` — какой Канвас этот Продукт операционализирует |
| `SvcTrack` | `pflow:Segment` | `Сегмент:` — маршрут какого Сегмента описывает Трек |
| `SvcPortfolio` | `pflow:Unit` | `Юнит:` — командная единица, которую отражает Портфель |

### Что выводится derived

| Сторона | Что показывается | Откуда |
|---|---|---|
| `Канвас.hover/inlay` | реализующие Услуги | `Service.Реализует` → `VPCSolution` → его VPC → Канвас (через `Канвас.VPC:`) |
| `Предложение.inlay` | реализующие Услуги | то же |
| `Работа.inlay` | использующие Услуги/Контексты | reverse-index |
| `Сегмент.inlay` | использующие Услуги/Персоны | reverse-index |
| `Услуга.hover/inlay` | покрывает Канвасы | `Service.Реализует` → `VPCSolution` → VPC → Канвас |
| `Ситуация.hover` | N Канвасов / N Юнитов / N Switch'ей / N svc-Контекстов | reverse-index по `Ситуации:` / `Ситуация:` / `SvcContext.Ситуация:` |
| `Предложение.inlay` | покрывающие Развилки | reverse-index по `Развилка.Влияет_на: [VPC]` (поля `Развилка:` на Предложении нет) |

Связь — одна декларация, обе стороны видны.

### Cross-layer валидаторы

- **Канвас не покрыт ни одной Услугой** — если у Канваса хотя бы одна VPC с Предложениями, и ни одна Услуга через `Реализует:` ни одно из них не реализует.
- **Услуга не указывает Реализует** — Услуга, не закрывающая ни одной стратегической гипотезы.
- **Действующая Услуга реализует непроверенное Предложение** — `Реализует:` на Предложение со `Статус: гипотеза`.

## Совместный пример

`units.pflow`:

```pflow
Сегмент: "Семьи в новостройке" {
  Описание: "семья 30–45 лет, недавно завезла ковры в новую квартиру"
  Размер:   500000
}

Работа: "чистый ковёр после ремонта" {
  Когда: "ремонт закончился, ковёр в строительной пыли"
  Хочу:  "вычистить, не повредить, не разбираться самому"
  Чтобы: "положить обратно и закрыть тему"
  Тип:   функциональный
  Сегменты: ["Семьи в новостройке"]
}

Ситуация: "После_ремонта" {
  Описание:  "Ремонт закончился, ковёр в строительной пыли — нужно вернуть в жилое состояние"
  Триггер:   "Бригада выезжает, в квартире стоит свёрнутый загрязнённый ковёр"
  ЛПР:       [Сегмент."Семьи в новостройке"]
  Работа:    "чистый ковёр после ремонта"
  Срочность: высокая
}

VPC: "Премиум B2C — чистка ковров" {
  Сегмент:      "Семьи в новостройке"
  Работы:       ["чистый ковёр после ремонта"]
  Альтернативы: ["YouTube гайды", "обычная химчистка"]
  УТП:          "вернём через сутки или вернём деньги"

  Предложение: "профессиональная химчистка" {
    Решает:   "чистый ковёр после ремонта"
    Подход:   "забор → чистка с тестом → возврат через 24ч"
    Статус:   работает
    Покрытие: полное
  }
}

Канвас: "Чистка ковров премиум-сегмента" {
  VPC:      ["Премиум B2C — чистка ковров"]
  Ситуации: ["После_ремонта"]
}

Результат: "Цветостойкость_после_чистки" {
  Работа:      "чистый ковёр после ремонта"
  Направление: избежать
  Что:         "случаи изменения цвета ворса после чистки"
  Цель:        "0 случаев в квартал"
}
```

`services.sflow`:

```sflow
Услуга: "чистка_ковров_премиум" {
  Статус:    действующая
  Работа:    "чистый ковёр после ремонта"
  Сегменты:  ["Семьи в новостройке"]
  Реализует: ["профессиональная химчистка"]
  Персоны:   ["Марина_квартира"]
  Контексты: ["после ремонта квартиры"]
  Обещания:  ["не повредим ворс и цвет"]
  Цена:      18000
  Период:    месяц
  Валюта:    RUB
}

Персона: "Марина_квартира" {
  Сегмент:  "Семьи в новостройке"
  Описание: "женщина 35–55, своя квартира, ковёр — часть интерьера"
}

Контекст: "после ремонта квартиры" {
  Работа:    "чистый ковёр после ремонта"
  Персоны:   ["Марина_квартира"]
  Ситуация:  "После_ремонта"        # cross-layer → pflow:Ситуация (структурный ref)
  Эмоция:    "досада, ковёр недешёвый"
  Триггер:   "разворачивание ковра"
  Что_важно: ["не повредить ворс"]
  Обещания: ["не повредим ворс и цвет" -> ключевое]
}

Обещание: "не повредим ворс и цвет" {
  Формулировка: "тест на скрытом участке + страховка"
  Кому:         ["Марина_квартира"]
  Закрывает:    ["Цветостойкость_после_чистки"]   # cross-layer → pflow:Результат
}
```

В редакторе:
- Hover на Канвасе «Чистка ковров премиум-сегмента» → «реализуют 1 Услуг(и) ([«чистка_ковров_премиум»])».
- Hover на Услуге → «покрывает 1 Канвас(ов)», «1 Сценари(я)» (если есть).
- Hover на Ситуации «После_ремонта» → «1 Канвас(ов)», «1 svc-Контекст(ов)» — сразу видно, есть ли продукт под GTM-сценарий.
- Hover на Результате «Цветостойкость_после_чистки» → inlay 🤝 показывает «закрывает 1 Обещани(й)» — видно, что ODI-ставка операционализирована.
- Если из Услуги убрать `Реализует:` — на Канвасе появится warning «не покрыт ни одной Услугой».
- Если из Контекста убрать `Ситуация:` — у Ситуации счётчик svc-Контекстов упадёт до 0.
- F2 на «Чистка ковров премиум-сегмента» → переименуется и в pflow, и в svcflow ссылках.
- F2 на «После_ремонта» → переименуется в `Ситуации:` Канваса, в `Ситуация:` Контекста и в любых путь-ссылках Сигналов.
- F2 на «Цветостойкость_после_чистки» → переименуется в `VPC.ERRC.Создать:` (если есть) и в `Обещание.Закрывает:`.
